# 5단계 사전 누락 점검 — 2026-10-01

## 핵심 화면 우선순위 복귀

후속 요청에 따라 핵심 화면 설계·구현 대조로 복귀했다. 입력 목적 분리, 인라인 오류, 수정 버튼 접근성, 부고의 조용한 완료 화면을 반영했다. `design/CORE-SCREEN-ALIGNMENT.md`에 여정별 검증과 남은 차이를 정리했다. 현재 자동 테스트 25개와 빌드 통과. 실제 모바일·복구와 독립 참석/안부 모델은 여전히 미완료다.

## 사용자 요청에 따른 진행 변경

2026-10-01 사용자 요청으로 프리뷰 로그인 검수는 건너뛰고 운영 계측 준비로 이동했다. 제공된 프리뷰는 Vercel 보호 로그인으로 연결됐으며 실제 모바일·복구는 미검증이다. 다음 단계 산출물은 `OPERATIONS-RELEASE-HANDOFF.md`, `OPERATIONS-METRICS.sql`, `../supabase/migrations/20261001_app_events.sql`이다. 자동 테스트는 21개와 빌드가 통과했다. DB·운영 배포 적용은 아직 수행하지 않았다. 아래 최초 사전 점검 내용은 당시 상태 기록이다.

이 문서는 연결된 최신 프리뷰와 실제 계정 복구 검수가 완료된 뒤의 최종 승인서가 아니다. 현재 그 검수를 시작하기 위한 환경을 확인하지 못해, 소스·자료 기준의 사전 점검 결과를 기록한다.

## 실제 확인한 환경

- PR #1은 Draft/open, 검수 시작 시 head=d2bccb4. 병합하지 않았고 PR 상태·댓글에서 프리뷰 URL을 찾지 못했다.
- 공개 `https://jebi-app.vercel.app/`를 직접 열었지만 이전 5장 온보딩이 표시됐다. 최신 3장 온보딩의 프리뷰로 간주할 수 없다.
- 모바일 폭·키보드·VoiceOver/TalkBack·이메일 링크 로그인은 실제 환경에서 검수하지 않았다.
- 자동 테스트는 서버와 이메일을 모의한다. 현재 코드 검증을 실제 계정 복구 성공으로 표현하지 않는다.

## 1. 핵심 화면 디자인 완성 — 설계 완료, 앱 전체 일치 확인 필요

완료: 기존 제비/같은 초가집 재사용, 4개 핵심 화면 보드·HTML, 3장 온보딩, 일정 우선 홈, 기억 우선 인연 상세.

미완료: 360/390/430px와 큰 글씨의 실제 레이아웃 비교, 입력 키보드에 가려지는 버튼, 부고의 전체 완료 효과 확인. 설계 HTML의 기록 목적 선택과 인연 상세의 안부 타임라인은 목표 설계이며 앱의 별도 일정/행동/금품 테이블로 모두 구현된 것은 아니다. 설계 보드의 모든 요소가 구현됐다고 단정하면 안 된다.

## 2. 사용자 여정 검수 — 모의 경로 검증, 실제 연속 여정 필요

완료: 일정 열기로 참석·지출 완료를 만들지 않는 홈, 금액 비교 선택 노출, 온보딩 저장 실패 잔류, 예시 데이터 격리 코드, CSV 왕복 테스트.

미완료: 같은 QA 계정에서 첫 방문→예시→실제 첫 기록→참석/안부→실제 금품→다른 날 재방문→이메일 복구를 연속 검증. 현재 가장 가까운 일정 선택·과거 일정 알림·박 상태가 동일한 행사에서 기대대로 연결되는지 실데이터 검수가 필요하다. 향후 완전한 데이터 분리를 위해 마이그레이션과 기존 기록 귀속 정책이 필요하다.

## 3. 개발자 전달 자료 확정 — 자료 존재, 구현 대조와 종료 조건 필요

완료: `docs/design/DEVELOPER-HANDOFF.md`, 이미지 적용표, 문구, 상태·동작·검수 기준, `docs/RESTORE-QA-2026-10-01.md`.

미완료: 개발자가 최신 프리뷰에서 화면별 일치/차이를 기록하고 날짜/서명과 캡처를 남겨야 한다. 기록 목적 선택과 데이터 구조의 목표/현 구현 차이를 해결하거나 후속 범위로 명시해야 한다. 테이블 지원 부족 시 필드가 사라지는 폴백은 출시 정책으로 허용할지 확정해야 한다.

## 4. 구현 및 검증 — 코드/자동 검사 완료, 실환경 검수 차단

완료: 접근성·화면·CSV 16개 테스트와 빌드, 이번 인증 사전 점검 3개 추가. 총 19개 테스트 통과. 운영 도메인에 고정된 이메일 복귀 주소를 현재 origin 또는 명시된 환경변수로 설정하도록 개선했고, 복구 로그인이 미등록 이메일로 새 계정을 만드는 동작을 막았다. 익명 기록 스냅샷 읽기 실패를 빈 계정처럼 처리하지 않고 로그인 진행을 멈추도록 수정했다.

미완료: Supabase에 정확한 프리뷰·운영 복귀 URL 등록 확인, 실제 이메일 확인/로그인, 같은 user id와 기록 유지, 다른 브라우저 복구, 익명→기존 계정 병합·재시도, DB 옵션 컬럼 지원 여부, RLS 소유권·다른 계정 접근 차단, 실패 후 반쪽 저장/중복 생성 여부.

프리뷰는 독립 QA Supabase 프로젝트 또는 명확히 분리된 QA 계정을 사용한다. 비밀번호·인증 토큰·메일 확인 링크를 문서나 채팅에 적지 않는다. 안전한 브라우저 로그인 절차로 확인한다.

## 5. 배포 및 운영 지표 설정 — 배포 보류, 측정 기준 확정안

배포: 실제 검수 완료 전 main 병합·운영 배포 보류. 배포 시 이전 배포 복귀 방법, DB 변경 되돌림/백업, 서비스워커 캐시 갱신, 로그인 복귀 경로와 장애 안내 확인이 필요하다. 푸시 발송 초안은 별도 인증·빈도·중복 방지 검토 전에 켜지 않는다.

운영 간극: `lib/metrics.js`는 app_events에 쓰지만 제공된 schema.sql에는 app_events 생성문이 없다. 테이블 미존재 시 측정을 조용히 건너뛰는 구조여서 이벤트 함수가 있다고 데이터가 수집되고 있다고 볼 수 없다. 온보딩 첫 실제 저장의 성공 이벤트, 재방문 일정 확인 이벤트의 연결도 대조해야 한다. 실제 계측 수집·집계 대시보드가 없으면 운영 지표 설정 완료로 표시하지 않는다.
