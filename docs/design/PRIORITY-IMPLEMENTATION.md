## 개발자 배포 순서
1. `supabase/migrations/20261002_record_semantics.sql`을 검토·적용한다. attendance/date_precision/asset_kind만 추가하며 기존 행을 추정 변환하지 않는다.
2. 테스트와 production build를 통과한 브랜치를 프리뷰에 배포한다.
3. 제휴 계약 확정 시에만 NEXT_PUBLIC_PARTNER_NAME, NEXT_PUBLIC_PARTNER_URL(HTTPS)을 설정하고 다시 빌드한다. 기본은 비활성. 개인정보를 URL에 넣지 않는다.
4. 일정 저장→참석 변경→별도 금품 저장→수정→재접속→CSV 왕복을 실제 테스트 계정으로 검수한다.
5. 위 표의 실제 검수를 통과하기 전 배포 완료/사용자 여정 완료로 판정하지 않는다.

## 디자인 및 상태 규격
- 초가집은 house_empty.webp 하나를 기본으로 사용. 건축 형태를 바꾸지 않는다. 답한 마음 1건 이상이면 옅은 따뜻한 배경을 겹친다. 취소하면 원상태로 돌아간다.
- 제비는 jebi_perched.webp를 길잡이로 사용. 송금/구매 승인이나 실제 메시지 전송을 암시하지 않는다.
- 박은 같은 지붕 위치의 contain 이미지. 최대 5개 표현이며 전체 개수는 숫자로 보완한다. 금액 크기는 이미지 크기에 영향을 주지 않는다.
- 부고 첫 저장은 조용한 제비 이미지, 축하 애니메이션 없음. reduced-motion 사용자는 진입/새싹 애니메이션 없음.
- 저장 실패는 입력을 보존하고 시트 안에 오류 표시. 성공한 경우에만 닫고 목록을 갱신한다.
- 제휴 복귀는 구매 증거가 아니다. 실제로 전한 경우에만 사용자가 방향/방식/금액을 확인하고 저장한다.

## 명시적 한계
- 일정·참석·금품은 기존 maeums 저장 구조 위의 논리적 분리다. 별도 occasions 테이블/영구 행사 ID 연결은 아직 없다. 동일 행사에서 생성한 금품은 인연/행사/날짜를 복사하며 원본 수정이 자동 전파되지 않는다.
- 기존 모호한 행을 자동 변환하지 않는다. CSV는 이미지·계정·박씨 연결까지 복구하는 전체 백업이 아니다.
- 제휴 복귀 안내는 열린 상세 화면의 세션 안에서만 유지된다. 브라우저 강제 종료 후 복귀 상태 복원은 아직 없다.
- 기존 HTML/PNG 디자인 보드에는 이 변경이 모두 재렌더링되지 않았다. 이 문서와 구현 코드가 최신 동작 기준이다.
- 운영 DB migration 실행, 실제 계정 복구, 연결된 프리뷰 모바일 검수는 이번 소스 검증에 포함하지 않았다.
