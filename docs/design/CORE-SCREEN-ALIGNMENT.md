# 핵심 화면 설계·구현 대조와 여정 검수

2026-10-01. 사용자 요청에 따라 디자인 구현 차이 정리로 우선순위를 복귀했다. 프리뷰 로그인 검수는 이전 요청대로 건너뛰었다. 아래는 소스와 모의 테스트 결과이며 실기기 화면 검수 결과가 아니다.

## 1. 핵심 화면 디자인

| 화면 | 설계 의도 | 구현 결과 | 남은 차이 |
|---|---|---|---|
| 온보딩 | 설화의 정서→실용성→첫 기록 | 3장, 기존 초가집·제비, 예시 저장 격리, 저장 실패 잔류. 실제 일정 저장 뒤 일정 안내. 부고에는 조용한 제비·빈 집·중립 완료 문구 | 모바일 글줄·키보드·큰 글씨·낭독기 확인 |
| 홈 | 다음에 누구를 챙길지 우선 | 가까운 일정·미정 날짜를 집 위에 표시. 일정 열기로 상태를 바꾸지 않음 | 모바일 화면 대비·작은 상태 글씨 대조, 참석·안부 여정 실환경 확인 |
| 입력 | 일정과 실제 금품 구분 | 목적 선택 카드. 일정은 금액/전달 방식/계좌/박씨 저장 제외, 실제 금품은 최소 증거 요구. 0원 허용. 수정 버튼과 이름 있는 입력, 인라인 실패 안내 | 실제 전달일과 행사일의 별도 모델, 참석·안부의 독립 기록, 기존 일정에 금품을 연결하는 데이터 구조 |
| 인연 상세 | 기억 먼저, 금액 비교는 선택 | 기억 기본 모드, 정산 선택 후 비교 표시 | 안부 타임라인 완전 분리, 실제 저장 후 목록 연결 확인 |

추가 이미지 생성 없이 기존 제비/같은 초가집 이미지를 사용했다. 시각 보드·HTML은 목표 설계 자료이며 실제 앱 캡처가 아니다. 일정/금품은 현재 동일 maeums 저장 구조를 사용하므로 화면 분리가 별도 테이블 구현이나 데이터 연결 완성을 뜻하지 않는다.

## 2. 검수한 사용자 여정

| 경로 | 자동 검증 | 실환경 상태 |
|---|---|---|
| 첫 방문→온보딩→직접 입력→저장 실패 | 확인 단계 유지, 성공 화면 없음 | 미검증 |
| 홈→가까운 일정→인연 상세 | 클릭 콜백·상태 변경 없음 | 미검증 |
| 인연→기억→정산→기억 | 비교 카드 선택 노출 | 미검증 |
| 입력→일정 목적→저장 | 이전 전달 방식 기본값이 있어도 금품 속성 null | 미검증 |
| 입력→금품 목적→빈 정보→0원 저장 | 빈 정보 오류, 0원 실제 기록 유지 | 미검증 |
| 입력→서버 실패→재시도 가능한 화면 | 입력 유지·role=alert 오류 | 미검증 |
| 부고→실제 저장→완료→내 집 안내 | 축하 성장 클래스 없음, 풍성한 박 약속 없음 | 미검증 |
| 금액 미상 선물→미지원 DB | 저장 실패를 알림. 전달 방식을 버려 일정으로 저장하지 않음 | 모의 DB만 검증 |
| CSV 내보내기→가져오기·중복·잘못된 값 | 기존 왕복 테스트 통과 | 실제 계정·DB 검증 필요 |

검증 결과: 로컬 자동 테스트 총 25개 통과, production build와 diff check 통과. 실제 서버·메일·모바일 검증을 대체하지 않는다.

## 3. 종료 조건과 남은 순서

1. 참석/안부 독립 기록과 기존 일정의 금품 연결 범위를 별도 명세로 확정한다. 현재 화면 입력 두 목적을 전체 모델 완성으로 오인하지 않는다.
2. 실제 최신 프리뷰 접근이 가능해질 때 360/390/430px·키보드·큰 글씨와 4개 화면을 대조한다. 현 브라우저 차단을 통과로 기록하지 않는다.
3. 합성 QA 계정에서 첫 기록→참석/안부→실제 금품→재방문→복구의 연속 여정을 수행한다. 실제 사용자 기록은 테스트 데이터로 쓰지 않는다.
4. 관찰 사용자 5명으로 컨셉·첫 기록 이해를 확인한다. 자동 테스트로 온보딩의 매력도나 사용자 이해도를 증명하지 않는다.
5. 단계별 결과와 캡처가 확보되기 전까지 ‘디자인/여정 최종 완료’는 보류한다. 개발자 전달 자료와 운영 계측 준비 자료는 유지한다.
