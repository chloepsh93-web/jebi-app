# 제비 핵심 화면 개발 지시서 v1

작성: 2026-10-01. 기준: main 7bd0e7e 및 후속 접근성 PR #1. 이 문서는 시각 설계, 사용자 여정, 개발 범위와 출시 조건을 한곳에서 정의한다.

## 1. 작업 문제 정의

사용자가 이해해야 할 것은 ‘돈을 갚으면 박이 열린다’가 아니라 ‘관계를 챙기는 기억을 남기고 다음 소중한 순간을 놓치지 않는다’이다. 흥부·놀부 설화는 정을 건네면 복이 돌아온다는 정서적 배경이다. 현실의 구매나 지출이 보상·관계 점수·재물을 보장한다는 의미로 쓰지 않는다.

요구사항 정제본: 기존 초가집·남색 제비 이미지 체계를 유지하면서 경조사 일정, 참석·안부, 실제 주고받은 돈·선물을 구분한다. 첫 방문에서 앱의 실용성과 감정을 함께 전달하고, 홈에서 다음 행동을 찾아주며, 인연 상세는 기억 중심으로 연다. 부고에는 축하 효과를 쓰지 않는다. 디자인 소스, 문구, 모든 주요 상태, 현재 Next.js 컴포넌트 대응, 검증 기준을 제공한다. 1,000명·활성 50% 목표는 기간과 행동 정의를 먼저 정하며, 제휴 구매는 핵심 경험 뒤에 선택적으로 제공한다.

산출물: `JEBI-Core-Screens.html`(단일 파일, 이미지 내장, 서버 연결 없는 상호작용 설계), `JEBI-Screen-Overview.png`(정적 설계 보드), 이 지시서, 앱 코드 수정 및 테스트. 설계 보드는 운영 화면 캡처가 아니다.

## 2. 디자인 판단 기준 — 아래 순서로 리뷰

| 순서 | 질문 | 통과 기준 |
|---|---|---|
| 1 세계관 | 정을 챙기면 관계가 자란다는 의미가 전달되는가 | 동일 초가집과 제비를 사용. 초대 수신·금액 크기·구매만으로 복이 늘지 않음 |
| 2 여정 | 이번 화면에서 다음 행동이 분명한가 | 주요 버튼 하나, 탈출 경로 하나. 첫 기록 후 홈에서 다시 찾을 수 있음 |
| 3 정보 | 실제 상태를 과장 없이 보여주는가 | 일정·참석·금품·금액 미입력 분리. 저장 실패를 성공처럼 처리하지 않음 |
| 4 시각 | 기능을 이해하면서 감정이 남는가 | 삽화는 서사, 명확한 텍스트는 기능. 금액 대시보드보다 인연·일정을 우선 |
| 5 접근성 | 터치·키보드·낭독기·큰 글씨로 가능한가 | 44px 이상, 현재 슬라이드만 읽힘, 창 포커스 관리, 색 외 상태 표현 |
| 6 사업성 | 핵심 가치 뒤에 자연스러운 수익 연결인가 | 먼저 기록·챙김. 구매 링크는 선택이고 구매 완료·돌봄 완료로 추정하지 않음 |

경쟁 금융관리앱과의 차별점은 합계의 정밀함을 버리는 것이 아니라, 정보를 ‘언제 누구를 챙길까’의 순서로 보여주는 것이다. 최신 경쟁 제품을 대상으로 한 비교조사 결과를 의미하지 않는다.

## 5. 핵심 화면 명세

### S01 온보딩 — 정서, 효용, 첫 행동

첫 장: ‘마음을 챙기면, 인연이 자라는 집’. 설화 연결 한 문장과 기존 초가집. 두 번째 장: ‘소식을 건네고, 일정을 기억해요’. 세 번째 장: ‘기억한 마음이, 다음 인사로 이어져요’. 3장 후 첫 소식 입력, 언제든 건너뛰기, 예시 체험 제공.

앱 컴포넌트 `Onboarding.jsx`. 현재 슬라이드만 렌더링, 단계 버튼 44px. 예시는 실제 인연·마음·합계에 저장하지 않는다. 최종 실제 저장은 이름·경조사를 확인한 뒤 수행하며, 실패 시 확인 단계에 그대로 남고 재시도 안내. 성공 후에만 완료 장면. 실제 저장 실패를 로그만 남긴 뒤 성공 애니메이션으로 넘기면 출시 불가.

### S02 홈 — 오늘 챙길 마음을 먼저

표시 순서: 제목/앱 내부 알림 → 가장 가까운 일정 → 날짜 미정 확인 → 초가집/짧은 서사 → 상태 요약 → 박씨·기억/선택 제휴 → 기록 CTA. 일정 클릭은 상세 이동이며 참석·지출 상태 변경이 아니다. 금액이 있든 없든 자동 ‘준비 완료’ 체크표시는 쓰지 않는다.

`Home.jsx`: 기존 일정 블록을 집보다 위로 이동. 빈 홈에는 ‘첫 소식 기록하기’ 안내. 용어 설명은 펼쳐볼 수 있게 제공해 모든 재방문마다 긴 설명을 강요하지 않는다. 현재 박 집계의 의미를 일정 개수로 바꾸어 표시하지 않는다. 부고 일정의 본문은 ‘조문 일정 확인’, 감사·축하 과장 금지.

### S03 입력·확인 — 무엇을 저장하는지 분명하게

순서: 기록 목적 → 상대 → 경조사 → 날짜/미정 → 장소/메모 → 실제 돈·선물인 경우 방향·방식·금액. 자연어 분석은 초안이며 최종 확인은 사용자에게 있다. 같은 이름은 명시 선택. null은 미입력, 0은 실제 0원. 돈·선물 저장 시 실제 주고받은 날짜와 행사의 날짜를 구분하는 것이 후속 모델 목표다.

`AddMaeum.jsx`, `DateField.jsx`, `Onboarding.jsx` 연결. HTML의 기록 목적 선택은 목표 설계이며 현재 DB의 별도 occasions 테이블이 구현됐다는 뜻이 아니다. 이번 앱 변경은 스키마를 바꾸지 않는다. 장기 목표인 일정·행동·금품의 완전 분리는 별도 데이터 마이그레이션 작업으로 진행한다. 이미지 첨부가 세션 전용이면 화면에서 지속 보관을 약속하지 않는다.

### S04 인연 상세 — 관계를 비교하지 않고 기억하기

아바타/이름/관계 → 기록 추가·인연 수정 → 기억/돈·선물 보기 → 타임라인. 기본 기억 화면에는 누가 더 줬다는 문장을 앞세우지 않는다. 금액 요약은 사용자가 ‘정산’ 모드를 고른 뒤 보여준다. 금액 미입력 건수는 합계와 함께 표시. 참석·안부와 금품을 구분해 읽힌다.

`YeonDetail.jsx`: 금액 차이 카드 노출을 mode=정산으로 제한. 사용자 선택의 기존 모드 저장은 유지. 설계 HTML의 ‘돈·선물 기록’ 라벨은 차기 용어 후보이며 앱 데이터 구조 변경 없이 모든 항목을 금품으로 재해석하지 않는다.

## 8. 구현 범위와 다음 게이트

이번 반영: 3장 온보딩, 실제 저장 오류 안내, 홈 일정 우선 배치, 준비 완료 과장 제거, 상세 금액 요약 선택 노출. 이전 PR의 접근성·복구 카피·CI와 함께 검증한다. 프로토타입과 보드는 목표 정보구조를 설명하며, HTML은 독립 예시다.

개발자는 main을 직접 배포하지 말고 PR 프리뷰에서 360/390/430px, 큰 글씨, iOS 키보드, VoiceOver/TalkBack, 부고, 저장 실패, 예시 격리를 확인한다. 브라우저 환경 차단 때문에 수정 화면의 시각 검수는 현재 미완료이며 이 한계를 통과한 것으로 표시하지 않는다. 실제 Supabase 접속 테스트 역시 별도 필요하다.

활성화 제안 정의: 가입 7일 내 실제 첫 기록 저장. 재사용 제안 정의: 가입 28일 내 첫 기록 이후 다른 날 일정 확인 또는 추가 기록. 1,000명의 50% 목표는 두 지표 중 무엇을 채택할지 운영 대시보드에서 구분한다. 현재 목표 달성 실적은 없다. 고객 평가 4.5는 설문이 아니라 실제 스토어 평점과 리뷰 수로 측정한다.

개인정보를 분석 이벤트에 넣지 않는다. 이벤트는 화면 진입·예시 시작·첫 실제 저장 성공·재방문 확인 수준으로 제한한다. 제휴 클릭은 구매 또는 관계 챙김 완료로 집계하지 않는다.
