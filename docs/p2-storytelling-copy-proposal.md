# P2 스토리텔링 반영안 — 카피 제안 초안 (기획팀)

- 기준: P1 컨셉 감사 결과 (코드 내 실제 문구 기반)
- 컨셉 기준: 흥부전 설화 — "제비가 새 박씨를 물어왔어요" / 박씨=정의 순환의 씨앗 / "정이 돌아온다" / 세계관 언어(박·마음·인연·제비)
- 판단 기준: "'정'을 강화하는가, 가계부로 만드는가?"
- 제약: 모바일 짧은 카피. 숫자는 숨기지 않되 문장으로 번역하는 기존 원칙 유지. 평상시는 절제 — 매 화면 설화 인용 금지.
- 코드는 수정하지 않음. ★ = 1순위 안.

## 2. "정산 모드" (YeonDetail.jsx:141) → "마음 돌아보기"

현재: "마음 모드" / "정산 모드" 토글 (aria-label "요약 모드"). 정산 뷰는 건별 전한/받은 표(날짜·경조사·전한/받은·금액).
- ★ "마음 돌아보기"
- 2안 "인연 돌아보기"
- 3안 "마음 살펴보기"
- 근거: "정산"은 명백한 가계부 어휘. Me 메뉴 "올해의 인연 돌아보기"(Me.jsx:145)가 이미 '돌아보기' 어휘를 쓰고 있어 앱 내 통일 효과가 큼. opt-in 배려는 유지 — 토글 UI와 기본 '마음 모드'는 그대로 두고, 숫자 표 뷰는 사용자가 직접 선택해야만 열리도록.
- 연관: aria-label "요약 모드" → "보기 모드" 정도로 함께 손보는 것 제안 (선택).

현재: 마음·박·인연만 정의됨. compact 모드가 Home(compact)과 온보딩 슬라이드4에 렌더됨.

- 2안 "이 집 지붕 위에 사는 소식꾼"

### 박씨
- ★ "흥부전처럼, 정을 싣고 돌아온 씨앗"

## 8. 푸시 카피 세트안 (문구안만 — 푸시 미도입 상태)

현황: Me.jsx:18 주석 "다가오는 소식을 제비가 알려드려요"만 존재. 푸시 구독 수집 UI의 hint("다가오는 경조사를 미리 알려드릴게요/드릴까요?")는 이미 톤 정합.
형식: title / body (모바일 짧은 카피, 금액 언급 금지, D-n만 노출).

### a) 다가오는 경조사 알림
- ★ title "제비가 소식을 물어왔어요" / body "{이름}님의 {경조사}가 {D-n}일 남았어요"
- 2안 title "다가오는 소식이 있어요" / body "{경조사} · {이름}님 — {D-n}일 전"

### b) 박 열림 알림 (due)
- ★ title "박이 익었어요" / body "{이름}님과의 박이 익었어요. 전할 때가 왔어요"
- 2안 title "전할 때가 왔어요" / body "{이름}님께 마음을 전할 때예요"

### c) 박씨 알림 (돌아온 정)
- ★ title "제비가 새 박씨를 물어왔어요" / body "{이름}님께 전한 마음이 박씨가 되어 돌아왔어요"
- 2안 title "정이 돌아왔어요" / body "{이름}님과의 정이 박씨가 되어 돌아왔어요"

- 근거: 컨셉 기준 문구 "제비가 새 박씨를 물어왔어요"를 푸시 타이틀로 직접 사용 — 흥부전 서사의 앱 내 최대 노출 지점(잠금화면)이 됨. "정이 돌아온다"는 2안 타이틀로 배치. 주석 문구 "다가오는 소식을 제비가 알려드려요"는 a) 세트의 모태로 승격.

## 기획팀 메모 (디자인·개발 전달 시 유의)
1. 1순위 안들은 전부 '전할 때' 어휘 체계로 통일됨 — due 관련 신규 카피 작성 시 기준어로 사용할 것.
2. '돌아보기' 어휘 체계: "마음 돌아보기"(인연별) ↔ "올해의 인연 돌아보기"(연간) ↔ "우리 집 돌아보기"(결산 대체). 세 곳이 한 세트.
3. Glossary full/compact 렌더 분기는 디자인팀과 협의 필요 (4번 유의사항).
4. Onboarding.jsx:51 '결산이 돼요' 잔재는 3번과 함께 수정되어야 함 — 놓치기 쉬운 포인트.
5. 과한 세계관 금지 원칙 하에, 의도적으로 설화를 전면에 내세운 곳은 단 두 곳: 온보딩 슬라이드5(박씨·기존 유지)와 푸시 c) 타이틀. 나머지는 어휘 수준에서만 반영.
