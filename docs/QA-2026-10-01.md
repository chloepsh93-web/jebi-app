## 검증과 한계

- node:test + jsdom 5개: Tab 순환, 취소 초기 포커스, 중첩 창 Escape, 포커스 복귀, 배경 포커스 방지, 빈 창, 역순 정리와 스크롤 복귀.
- production Next.js build 통과.
- 공개 배포 앱의 온보딩을 직접 확인. 배포 앱의 문구 일부는 저장소와 달라 최신 커밋 배포 여부를 별도 확인해야 한다.
- 로컬 프리뷰는 검토 브라우저의 ERR_BLOCKED_BY_CLIENT로 접근 불가. 수정 화면의 모바일 시각 검수와 실제 Supabase CRUD·매직링크 복구는 미완료.
- jsdom 검증은 실제 화면 낭독기나 모바일 실기기 검증을 대체하지 않는다.
- 이번 브랜치는 서버 테이블·사용자 기록·제휴 링크·푸시 발송 설정을 변경하지 않는다.

## Vercel 프리뷰 검수 순서

1. 360/390/430px에서 첫 온보딩의 이미지·제목·설명·다음 버튼, 5개 단계 전환과 큰 글씨 모드를 확인한다. 작은 높이에서는 스크롤로 모든 조작에 접근해야 한다.
2. VoiceOver/TalkBack에서 현재 슬라이드 하나만 읽히고 단계 버튼 이름과 선택 상태가 안내되는지 확인한다.
3. 키보드로 설정 메뉴와 시트를 연다. Tab/Shift+Tab이 시트 안에서 순환하고 Escape로 닫은 뒤 진입 버튼에 복귀하는지 확인한다.
4. 시트 위 확인창을 열고 Escape와 브라우저 뒤로가기를 각각 시험한다. 최상위 창 하나만 닫혀야 한다. 취소에 초기 포커스가 있어야 한다.
5. 익명 기록 생성 후 이메일 연결·매직링크 로그인을 검증한다. 다른 브라우저에서 연결된 이메일로만 같은 기록에 재접근할 수 있어야 한다. 실제 사용자 데이터 대신 전용 QA 계정을 사용한다.
6. 초대장 저장·참석·금전 기록이 각각 어떤 데이터와 집계로 변환되는지 별도 검토한다. 참석만으로 지출액을 추정하거나 돈의 크기로 관계의 가치를 평가하면 안 된다.

## 다음 우선순위

출시 전에는 기존 마음 모델의 일정·금품 혼합을 점검하고, 실제 알림 전달과 단순 앱 내부 안내를 구분해야 한다. send-due-push 초안은 CRON_SECRET 미설정 시 호출을 허용하며 반복 발송 제한도 아직 보장하지 않는다. 별도 인증·발송 중복 방지 검토 없이 운영 배포하지 않는다.

초기 목표의 ‘활성 사용자 50%’는 기간과 행동이 미정이다. 출시 측정안은 가입 후 7일 이내 첫 실제 기록 저장을 활성화, 이후 28일 내 일정 확인 또는 추가 기록을 재사용으로 나눠 정의한다. 수치는 목표 정의안이며 달성 실적이 아니다. 경조사 앱은 사용 주기가 길어 DAU만으로 성공을 판단하지 않는다.

## 핵심 화면 설계 후속 반영

디자인 보드와 단일 파일 프로토타입, 이미지 적용표와 여정 명세를 `docs/design/`에 추가했다. 온보딩을 세 장으로 줄이고, 저장 실패 시 성공으로 넘어가던 경로를 차단했다. 홈은 일정 우선으로 배치하며 자동 준비 완료 문구를 제거했다. 인연 상세의 금액 차이는 정산 모드에서만 표시한다.

검증 갱신: 테스트 8개 통과(접근성 5 + 실제 React 컴포넌트 통합 3), production build 통과. 통합 테스트는 Supabase 쓰기 실패를 모의하며 실제 계정 데이터와 네트워크를 사용하지 않는다. 정적 설계 보드의 이미지·글자를 직접 확인했다. HTML의 4개 화면/중복 없는 제어 ID/이미지 내장을 검사했다. 수정된 앱 화면의 실기기 시각 검수와 실제 서버 검증은 여전히 미완료다.
